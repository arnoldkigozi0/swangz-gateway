# Tracker → Swangz AI Hub feature parity

## Audited baseline

Gateway main: `5c6a3d0b937249d3e6640b6ca878e4bbf1a34673` (PRs #4 and #5 inspected). Tracker main: `95cba831a77fd47f9499963ae9dfef9761d4e57b`. Work continues on `feature/hub-tracker-parity`; production data and its checkout are separate and unchanged.

The reference is the complete 21,013-line `index.html`, its project instructions, `supabase/schema.sql`, deployment/install documentation and Git history. There are 620 named function declarations, including repeated overrides and internal UI helpers. Later overrides matter: the final staff report flow does not expose all the earlier financial forms, whereas the final request flow includes expected effort and published plan selection. Hub retains optional defensible financial declarations, and adds a separately authorised financial correction workflow. It does not copy obsolete client-side permissions.

## Native work areas

Staff: Home → Tools → Weekly reports → Adoption & impact → Projects → Requests → Activity → Studio → Devices → Privacy/help. Weekly accountability and long-term adoption remain separate record types. Procurement is a tab under Requests; ordinary existing-tool access remains its own tab and backend.

Admin: Weekly reporting handles compliance and frozen evidence. Business value handles adoption, departmental comparisons, projects, financial estimates, registry reconciliation and report management. Tool & subscription requests handles purchasing. People, Tools/licences, Spend, Security, Audit and Settings retain their existing responsibilities. Record details open deliberately; analytics do not stack onto Overview.

## Historical recovery exception

Recovered browser records are preserved with import provenance. A DNS failure is evidence of endpoint unavailability, not proof that the Supabase project was deleted. The inspected history has no usable alternate project. The old backend is needed only to verify missing history; it does not block normal native Hub functions. No production reconciliation or complete recovery is claimed.

Use `python3 -m gateway.tracker_recovery` for sanitised configuration/history DNS diagnostics, and `python3 -m gateway.hub_import` for read-only export, dry run, backed-up transactional import and v19→v20 typed metadata backfill. Imported reports remain adoption declarations. Demo rows skip only explicit markers; conflicting source IDs never silently overwrite a prior declaration or restore an archived record.

The declaration-level inventory (all 620 named source declarations and the additional detail builders) is in [TRACKER-FUNCTION-INVENTORY.md](TRACKER-FUNCTION-INVENTORY.md).
