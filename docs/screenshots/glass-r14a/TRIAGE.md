## Why the current draft cannot use its old acceptance evidence

1. **The measured scene is superseded.** The saved screenshot shows the older expanded console sidebar, architecture scene, strong pale panels and old typeface. The canonical target uses `room-warm.webp`, Poppins and the specified glass/scene opacity. Contrast is a foreground/background relationship: the historical light-line3.59:1, spark4.49:1 and bar-fill3.39:1 in the README do not establish current-room contrast. The PR description's bar-fill number4.16 also differs from the README's3.39 and needs a fresh, source-bound raw result rather than another copied summary.
2. **The sampler no longer covers the current column renderer.** `porcelain.cjs` mounts `SUI.columns`, then asks `measure(..., 'fill')` for `.u-chart .col`. Current `ui.js` creates `.u-tubes` and sets `bar.style.fill = url(#...-g)` (selected: `...-s`). The saved screenshots show the earlier solid columns, and the README explicitly says tube columns were not covered. A new run must measure the actual gradient/rim/selected state, not assume the old solid fill.
3. **Unsupported paint can escape the assertion.** `measure()` parses computed paint using `color.match(/[\d.]+/g).map(Number)` and treats the first three matches asRGB. A gradient URL is not anRGB colour. Missing components can propagateNaN through luminance and `worst`; `if (ratio < min)` does not fail forNaN, and JSON serialization can conceal it asnull. There is no `Number.isFinite` guard or explicit supported-paint validation. This is a source-level failure path, not a newly reproduced browser result. Fix unsupported-paint handling before trusting a future PASS; do not skip the new columns or lower thresholds to make it green.
4. **Scope is wider than the title implies.** The default spark stroke changes dark mode too, and `ui.css` is shared by both apps. The dark correction is disclosed in the README, but current acceptance must include the actual staff/admin uses and selected/zero/tone2 states. Tube inline fill takes precedence over the generic light `.col` CSS, so this triage does not claim that the patch flattens the tube gradients.
5. **CI does not run this contrast sampler.** The existing workflow has no `porcelain.cjs` step. Generic browser-job success alone cannot establish these proposed colour ratios, and no raw measurementJSON is committed alongside the four images. The harness performs numerical sampling only in desktop cells; the phone cells save screenshots. This is not a new assertion that the CSS fails contrast everywhere; it is a precise limit on the available evidence.
